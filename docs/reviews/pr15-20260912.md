# PR15 owner-review changes — 2026-09-12

Addresses the [graph-design review](https://github.com/hsliuustc0106/vllm-lt/pull/15#issuecomment-5629940930)
and [owner review](https://github.com/hsliuustc0106/vllm-lt/pull/15#issuecomment-5632504212).
The implementation snapshot is `af3327d5a30219bcc92c57deb43a10cc7be3040f`.

## Changes

- **Reserved-memory growth:** a controlled diagnostic identifies fresh capture
  streams as the source of 34 MiB of inactive default-pool storage per executor.
  Reuse a released stream only after synchronized, successful graph teardown.
  Simultaneously live executors keep separate stream leases and private pools.
- **Pool ownership:** one owned `torch.cuda.MemPool` serves all buckets in an
  executor. Replays are serialized, captured outputs are copied to external
  persistent destinations, and callers receive independent gathered outputs.
  Close resets every graph before dropping outputs and releasing the owner.
  Failed close retains both ownership and the stream lease.
- **Scheduler coverage:** persistent and graph execution share a power-of-two
  ladder derived from `SchedulerConfig.max_num_seqs`. The default eight live
  requests now fit physical bucket 16; 16-request capacity adds bucket 32.
  Odd-slot mapping remains explicit, including its padding cost.
- **Derived budgets:** tensor and metadata specifications supply allocation and
  byte accounting. A configurable graph budget bounds the complete ladder;
  the default common-buffer cap is now 1 MiB. Old frozen contracts retain their
  original limits and validation shapes explicitly.
- **Review surface:** buffer selection/allocation, CUDA resource ownership and
  diagnostic serialization/limits are separate modules. The profiler uses the
  executor selector and validates actual bucket inventory and graph identity.
- **Scope:** the PR description and roadmap explain that real gate readback and
  host routing remain synchronous. An observed ratio is not a theoretical ceiling.

## Validation

- **956 CPU tests passed**, 49 GPU tests skipped in that CPU-only invocation.
  CUDA discovery/initialization was blocked. Ruff lint, formatting and diff
  whitespace checks passed.
- **49 GPU kernel tests passed** on reserved GPU 2.
- **17 real-model create/close cycles passed**: one feasibility cycle and 16
  measured lifecycle cycles, using one resident model/cache and no cache drops.
  Post-close allocated memory remained 12,181,062,656 bytes and reserved memory
  12,218,007,552 bytes in every cycle. CUDA snapshots retained zero graph-private
  segments after each close. This demonstrates the declared fixed-concurrency
  plateau, not unbounded growth in concurrent engine count.
- **Live-gate correctness passed** at exit threshold 0.5: two eight-request waves
  per compact/graph configuration, real exit depths 3 and 4, exact token/depth
  agreement and finite returned tensors. Graph waves reached buckets 4/8/16.
  The second wave remained correct after constructing and closing another live
  graph executor with a different pool and capture stream.
- The lifecycle worker and both root-cause workers reached zero terminal CUDA
  allocation and reservation. The executor itself never drops global caches.
