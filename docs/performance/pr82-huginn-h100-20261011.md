# PR82 coda graph performance supplement — H100, 2026-10-11

Enabling only the coda CUDA graph improves end-to-end throughput by **0.342% at B1 and 0.845% at B4** in the fixed 32-loop workload. Full hidden states, vocabulary logits and all layer KV tensors match bitwise between coda off/on. The requested 10% end-to-end throughput improvement is **not reached**.

Both arms execute the original PR82 source at `681b695874c745a5494916aa0353109637da4db0`. Core graphs remain enabled; the sole ablation is setting `runner.coda_graphs = None` in the core-only arm. The delivery branch's production and existing test files match that measured commit exactly. The net supplement adds this report, JSON evidence, the reproduction harness and model manifest.

## End-to-end coda off/on

| Batch | Coda off, seconds | Coda on, seconds | Tokens/s, off → on | Throughput gain |
|---|---:|---:|---:|---:|
| B1 | 1.548568 | 1.543288 | 10.3321 → 10.3675 | **+0.342%** |
| B4 | 1.988788 | 1.972121 | 32.1804 → 32.4524 | **+0.845%** |

Each batch has ten measured pairs across two fresh processes, each with five warmups and five measured pairs. Batch order reverses B1/B4 → B4/B1; arm order alternates and reverses between processes. Overall, 80 raw arm trials include 40 measured arm trials (20 measured pairs). Throughput gain is the ratio of mean burst times minus one. Raw paired times and descriptive variability are included in the [JSON evidence](pr82-huginn-h100-20261011.json).

All measured requests produce exactly 16 tokens at depth 32 and reclaim all KV blocks. Measured graph captures and fallbacks are zero. Peak allocated memory is identical between arms: 12,814,654,976 bytes at B1 and 12,822,637,056 bytes at B4. Both engines are resident during each comparison, so these peaks are not single-engine deployment estimates.

The previously reported **7.36% / 8.02%** compared additional RMSNorm fusion and constant-exit readback removal against the original implementation, with coda graphs enabled on both sides. Those are combined optimization results and are **not coda graph gains**; those production changes are excluded from this supplement.

## Numerical consistency

The independent audit checked 1,080 binary tensor files forming 540 bitwise-equal coda-off/on pairs. Coverage includes B1/B4, two request-ID reuse waves and three generated tokens per request: complete 10,560-wide retained hidden states, all 65,536 logits and complete causal K/V for all eight layers. Tokens, exit depths, finish behavior, request reuse and KV reclamation were also checked.

This covers the fixed tested cases; it does not claim all possible prompts, dtypes or devices.

## Profiling

Four fresh processes profile the complete second decode token at B1: coda off/on, each with ops-only and full shape/memory/stack collection. All contain CPU and CUDA events and 32 core graph replays. The coda-enabled profiles contain one coda replay; the other profiles contain zero. Capture is complete before profiling, and these timings are excluded from the throughput results.

In the ops-only traces, CPU profiler events decrease from 4,771 to 4,200; CUDA events are 8,244 and 8,251 respectively. The captured coda/head graph contains 132 kernels with a GPU span of about 1.833 ms. Each of the 32 core replays contains 234 kernels and spans about 2.745 ms. These diagnostic spans show that core recurrence occupies most of the token's GPU execution; coda is a small fraction. Full per-graph breakdowns, event counts and trace hashes are in the JSON evidence.

## Fixed workload and timing boundary

One NVIDIA H100 with 67,952,836,608 bytes reported by CUDA. Torch `2.12.1+cu130`, Triton `3.7.1`, Transformers `4.54.1`. Model `tomg-group-umd/huginn-0125` at revision `bb6621b65e90b6a4b9b29ef88dc83866d450470c`; all 12 model files were hashed. BF16, TF32 disabled, 32 loops, greedy sampling, ignore EOS, four fixed prompts, B1/B4, 16 outputs per request. Native synchronous engine, Triton attention, LAST_EXITED KV, 1,024 blocks of 16 tokens, four sequence slots, 32 batched tokens and prefill chunks of eight. Each request owns a persistent seeded generator, reset identically per arm.

Timing includes request admission, all engine steps, CPU token delivery and KV reclamation, with CUDA synchronization around each burst. It excludes model loading, graph capture warmups, profiling, network serving and detokenization. These are H100 native-engine measurements; HTTP serving and A800 performance were not measured here.

## Reproduce

Set `CUDA_VISIBLE_DEVICES` to one reserved GPU. `$PR82_MODEL` must contain the pinned model files; the manifest is verified before execution. `$PR82_OUT` must identify new output directories. Run each command in a fresh process.

```sh
python benchmarks/huginn_pr82_review.py --model "$PR82_MODEL" --mode parity --output "$PR82_OUT/parity"
python benchmarks/huginn_pr82_review.py --model "$PR82_MODEL" --mode timing --start 0 --output "$PR82_OUT/timing-start0"
python benchmarks/huginn_pr82_review.py --model "$PR82_MODEL" --mode timing --start 1 --output "$PR82_OUT/timing-start1"

for arm in core_only core_coda; do
  for level in ops full; do
    python benchmarks/huginn_pr82_review.py --model "$PR82_MODEL" --mode profile --arm "$arm" --level "$level" --output "$PR82_OUT/profile-$arm-$level"
  done
done
```

The nine workload and measurement functions in this portable harness have identical ASTs to the executed frozen experiment. CLI paths and provenance binding are portable. Parity output includes binary tensors and SHA-256 indices for independent comparison.
