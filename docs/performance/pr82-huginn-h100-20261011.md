# PR82 Huginn H100 measurements — 2026-10-11

The combined Huginn changes improve end-to-end throughput by **7.36% at B1 and 8.02% at B4**, with bitwise-identical full hidden states, vocabulary logits and all layer KV tensors in the tested cases. Both arms in this comparison already have core and coda CUDA graphs enabled. These percentages must not be attributed to enabling coda graphs alone.

Production baseline: `681b695874c745a5494916aa0353109637da4db0`.
Measured candidate: `3a40fdf154981392d170bd8958675119051df2f1`.
Subsequent report/benchmark commits do not change production code.

## End-to-end comparison

| Batch | Original seconds | Candidate seconds | Tokens/s, original → candidate | Throughput gain | Latency reduction |
|---|---:|---:|---:|---:|---:|
| B1 | 1.544662 | 1.438773 | 10.3583 → 11.1206 | **+7.36%** | 6.86% |
| B4 | 1.973898 | 1.827274 | 32.4232 → 35.0248 | **+8.02%** | 7.43% |

Each batch has ten measured pairs across two fresh processes, each with five warmups and five measured pairs. Batch order is B1/B4 then B4/B1; arm order alternates and reverses between processes. Each process loads both exact production model classes and runners, verifies identical model parameters, and uses byte-identical shared dependencies. The separately loaded models remain resident throughout the comparison.

All 20 measured pairs improve throughput by more than 5%. The smallest paired gains are 7.27% for B1 and 7.84% for B4. Mean gains in the two independent process orders are 7.35%/7.37% for B1 and 8.13%/7.92% for B4. These are measurements of this fixed workload on one H100, not confidence claims across other hardware or workloads.

Peak allocated memory is identical between arms: 19,987,778,560 bytes at B1 and 19,996,070,400 bytes at B4. These peaks include both resident models and engines and are not single-engine deployment memory estimates.

## Separate coda graph ablation

Core graphs stay enabled in both arms; only `runner.coda_graphs` is disabled in the core-only arm. Each revision has its own two fresh processes and ten measured pairs per batch.

| Batch | Original coda-on gain | Candidate coda-on gain |
|---|---:|---:|
| B1 | +0.342% | +0.168% |
| B4 | +0.845% | +0.162% |

The standalone coda graph effect remains small. The 7–8% end-to-end improvement comes from consuming Huginn's constant zero exit hazard on CPU and fusing RMSNorm's epilogue throughout Huginn. Removing core-side readback stalls also lets eager coda work overlap queued GPU work, so the incremental coda-only gain becomes smaller.

## Changes and numerical checks

- Huginn has no learned exit gate. Its recurrent gate is `sigmoid(-1e4) == 0`; synchronous scheduling now consumes that declared constant without a device-to-host readback after every loop. Recurrent computation, KV bookkeeping, depth policy and sampling remain intact. Random lookahead signals still use the normal readback path.
- Huginn BF16 inference fuses the RMSNorm epilogue. It preserves PyTorch's original FP32 variance reduction, the BF16 rounding before weight multiplication, and disables multiply-add contraction. CPU, gradient-enabled and other dtype paths retain the reference implementation.
- A fully fused reduction was tested and rejected: token IDs stayed equal but 420/540 complete tensors differed. It is not in the production candidate.
- Candidate coda on/off: 1,080 raw tensor files, 540 bitwise-equal pairs. Original/candidate: another 1,080 files, 540 bitwise-equal pairs. Coverage is B1/B4, two request-ID reuse waves, three generated tokens, full 10,560-wide retained hidden state, all 65,536 logits, and complete causal K/V for all eight layers.
- All measured requests return exactly 16 tokens at depth 32 and reclaim all KV blocks. Measured captures and fallbacks are zero.
- 76 regression tests pass without skips: 48 Huginn/normalization, 14 Triton CUDA-graph/lifecycle, and 14 CPU FlashAttention selection/import tests. The separate FA3 compatibility commit supports the official flat module layout while preserving missing-binary import errors.

## Profiling

Four fresh candidate processes profile a complete second decode token at B1: coda off/on, each with ops-only and full shape/memory/stack collection. All contain CPU and CUDA events, 32 core replays and the expected zero/one coda replay. Profiling times are excluded from throughput results.

In the ops-only trace, kernels per core replay decrease from 234 to 170 and kernels in the coda/head graph from 132 to 92. Core graph GPU span decreases from about 2.745 to 2.642 ms; coda/head from 1.833 to 1.776 ms. These instrumented spans explain where work was removed; they are not end-to-end latency measurements. With 32 core iterations, coda occupies only a small part of the token's execution time.

## Fixed environment and workload

One NVIDIA H100, 67,952,836,608 bytes reported by CUDA; Torch `2.12.1+cu130`, Triton `3.7.1`, Transformers `4.54.1`. Model `tomg-group-umd/huginn-0125` at `bb6621b65e90b6a4b9b29ef88dc83866d450470c`, all 12 model files hashed. BF16, TF32 disabled, 32 loops, greedy sampling, ignore EOS, fixed original four prompts, B1/B4, 16 outputs/request. Native synchronous engine with Triton attention, LAST_EXITED KV, 1,024 blocks of 16 tokens, four sequence slots, 32 batched tokens and prefill chunks of eight.

The timing boundary includes request admission, all engine steps, CPU token delivery and KV reclamation, with CUDA synchronization around each burst. It excludes model loading, graph capture warmups, profiling, network serving and detokenization. There is no A800 claim or HTTP serving throughput claim.

## Reproduce

Use a reserved GPU and the pinned model files in `$PR82_MODEL`. The model manifest is checked before execution. Set `CUDA_VISIBLE_DEVICES` to exactly one GPU. Run each command as a separate process. `$PR82_OUT` must point to a new output directory; `$PR82_BASE` must be a clean checkout of the baseline commit.

```sh
python benchmarks/huginn_pr82_review.py --model "$PR82_MODEL" --mode parity --output "$PR82_OUT/parity"
python benchmarks/huginn_pr82_review.py --model "$PR82_MODEL" --mode timing --start 0 --output "$PR82_OUT/timing-start0"
python benchmarks/huginn_pr82_review.py --model "$PR82_MODEL" --mode timing --start 1 --output "$PR82_OUT/timing-start1"

for arm in core_only core_coda; do
  for level in ops full; do
    python benchmarks/huginn_pr82_review.py --model "$PR82_MODEL" --mode profile --arm "$arm" --level "$level" --output "$PR82_OUT/profile-$arm-$level"
  done
done

python benchmarks/huginn_pr82_compare.py --model "$PR82_MODEL" --baseline "$PR82_BASE" --mode parity --output "$PR82_OUT/compare-parity"
python benchmarks/huginn_pr82_compare.py --model "$PR82_MODEL" --baseline "$PR82_BASE" --mode timing --start 0 --output "$PR82_OUT/compare-timing-start0"
python benchmarks/huginn_pr82_compare.py --model "$PR82_MODEL" --baseline "$PR82_BASE" --mode timing --start 1 --output "$PR82_OUT/compare-timing-start1"
```

The nine workload and measurement functions in the public review harness have identical ASTs to the executed frozen experiment; CLI paths and provenance binding are portable. Parity output includes binary tensors and SHA-256 indices for independent comparison. Published aggregate evidence and all paired old/new timings are in [the JSON report](pr82-huginn-h100-20261011.json).
