# M3 inactive-row prerequisite — 2026-09-11

The compact-versus-padded FP32 comparison passed its frozen correctness gates:
**65/65 executions, 52/52 kernel evaluations and 28/28 numerical comparison
streams**. This accepts the inactive-row prerequisite of [M3 #6](https://github.com/hsliuustc0106/vllm-lt/issues/6).
It does not complete M3: persistent storage, capture/replay, bounded fallback
and end-to-end performance remain open. Normal generation still uses compact
rows. There is no BF16 qualification or speed claim.

## Change and experiment

The private prepared KV descriptor now distinguishes logical live rows from
physical tensor rows. Attention and KV scatter mask memory accesses before an
inactive address can be used. Inactive recurrent hidden states and gate logits
are finite zero; the runner gathers only live outputs into independent storage
in scheduler order. Padding creates no request, coda item or sampling operation.

The [interface design](../m3-inactive-rows.md) and [resolved protocol](https://github.com/hsliuustc0106/vllm-lt/blob/477fab49fbb633408a6cf452959d2e35e9d70cd9/docs/benchmarks/m3-inactive-contract-20260911.md)
define the scope, controls, finite matrix and stop conditions. The source was
frozen before the CPU probe and reserved device work:

## Numerical and isolation results

The 13 model cases contain **11 qualification cases and two excluded feasibility
cases**. Of the 28 comparison streams, **27 qualify the implementation and one
compares excluded feasibility cases**. All 133,776 recorded boundaries were
comparable; required numerical and actual-decision failures were both zero.
These counts include feasibility and are not independent statistical trials.
An independent raw scan confirmed 252 actual token/exit matches (243 from
qualification and nine from feasibility), including 27 live-routing points.

The dense oracle executes the unchanged L16-F0, L256-F0, L64-F2 and L128-F3
fixtures, plus L16-F0 with actual live gates. Each native side runs the mixed
four-fixture group with refill and without refill, then live-gated L16-F0.
Histories contain nine genuine predictions per trajectory; forced histories
consume eight supplied inputs, while live histories consume generated tokens.
The observation layer checks scheduler request/position/depth identity before
mapping physical rows back to logical rows.

Final logits pass the original FP32 `atol=0.001`, `rtol=0.0001` bounds, with
exact actual top1, exit and history requirements. Per-loop hidden/gate values,
per-layer observations and full populated KV prefixes remain finite. Their
numerical deltas are diagnostic: different dense GEMM row counts can alter
rounding, so this result does not claim whole-model bitwise identity.

The separate held-input matrix covers 13 layouts on each side and each backend
(Torch/Triton): zero/one live row, all-inactive and all-active batches, holes
between active rows, 1/4/8-row boundaries, 1/2/3/32-column tables, block crossings,
fragmented odd-numbered physical pages and contexts through 512 tokens.
Inactive Q/K/V inputs contain NaNs; padded addresses include -1 and 2**30.

All 52 evaluations pass exact active compact/padded attention agreement within
each backend, finite positive-zero inactive attention, and exact whole-cache
agreement with the CPU-constructed write/guard expectation. Each evaluation
checks 40 K/V chunks, covering neighboring guard pages, future slots and the
untouched physical layer. The independent audit verified all 2,080 chunks,
26 exact active A/B pairs and 118,784 positive-zero inactive output elements.
No invalid-address error or guard change was recorded.
The model tests additionally cover mixed recurrence depths and live publication.

`compute-sanitizer` and `cuda-memcheck` are unavailable on this host, including
the actual CUDA installation. **No memory-access-checker run was performed.**
Masked source accesses, invalid-address cases and guard hashes provide the
retained evidence; they do not replace the missing checker coverage.
