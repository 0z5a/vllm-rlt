# M2 metadata reuse results — 2026-09-11

The FP32 metadata candidate meets the frozen M2 correctness, structure and
performance gates. W1 throughput improves **21.06% and 20.19%** in the two
matched pairs, exceeding the required 10%. Every control observation improves,
and memory/setup deltas remain within budget. This supports adopting the
metadata subset through PR review; sampling/result-transfer changes are out of
scope. [Q1's BF16 diagnosis](../q1-20260911.md) remains open.

## What was compared

The candidate prepares one borrowed KV descriptor per Ouro recurrent traversal
and reuses its positions, addresses, tables and lengths across all 24 layers.
Layer-specific history checks, allocation identity checks, actual gates,
sampling, synchronous scheduling, LAST-EXITED propagation and the physical
cache layout remain intact. Public cache methods retain adapters. See the
[interface and execution workflow](../m2-metadata.md).

The [resolved contract](m2-contract-20260911.md) was committed and pushed before
device execution. Candidate B ran clean at
`2ef43db91655f7f575a3cabee6609a35faadaf0a`; control A ran clean at
`ad920fddfc15673a93e8601aeed5e6d7f11f6e6d`. A restores only the cache manager and
native Ouro model from Q1 commit `56b5456c23354193c38838781157e849956d2053`.
All other source bytes, including the shared inference/validation harness,
match. Contract/report commits are separate from these execution snapshots.

Both used the real
`ByteDance/Ouro-1.4B@574fa66cb8bf5abdc979642d01cf2b79b16bfab1` checkpoint in FP32,
physical GPU 7 (NVIDIA L20X), UUID `0e488755-d8ed-b688-81e7-8e377dc10fd5`, on
`dedicated-developjob-8gpu2-a029z-64896bc8cf-8p2lw` as `hsliu2`. The scheduler
assigned `cuda:0`. Python 3.12.13, Torch 2.13.0/CUDA 13.0, Triton 3.7.1 and the
prepared Q1 environment were fixed. CPU binding was 56–63, active NUMA memory
policy bound node 1, with one intra-op/inter-op thread, seed 0 and disabled
TF32/reduced-precision reductions. The explicit affinity and prepared environment
differ from historical M1; fresh A observations supply the comparison.

All **105/105 executions** completed: 27 numerical, 14 feasibility, 32 warmup,
28 measured and four profiles. Eight fresh processes ran sequentially in
N-A, N-B, A1, B1, B2, A2, P-A, P-B order. Each loaded one model once and used
fresh per-case engine/state with allocator/compiler caches retained within the
process. Numerical qualification preceded A1. No replacement trials ran.
Downloads, loading, warmups, numerical checks and profiles were excluded from

## Numerical and structural evidence

The offline audit verified **27 cases, 51 comparison trajectories and 243,495
selected boundaries**, with no required, behavior, nonfinite or incomparable
failures. The 17 exact B/A streams cover **81,165 boundaries**, including full
populated KV prefixes. Every selected B/A value agrees exactly. Oracle
comparisons retain Q1's original FP32 final-logit bounds (`atol=0.001`,
`rtol=0.0001`) and actual prediction/exit gates; intermediate oracle deltas
remain diagnostics.

Coverage includes fixed depths, adjacent shallow/deep forced exits, Torch and
Triton serial paths, packed refill/no-refill, and actual live gates. Each
trajectory records nine genuine predictions. Fixed/forced histories consume
eight supplied continuation inputs; live cases consume generated histories.
All genuine compared predictions and exit decisions agree. This finite subset
qualifies the selected FP32 change, not BF16 or task quality.

The four complete profiles have matched capture windows and execution work:

| Profile | Recurrent traversals | Writes / attention calls | B preparations | Metadata + position HtoD copies, A → B | Matching stream synchronizations, A → B |
| --- | ---: | ---: | ---: | ---: | ---: |
| W1/refill | 64 | 1,536 / 1,536 | 64 | 6,208 → 320 | 6,208 → 320 |
| W4/refill | 27 | 648 / 648 | 27 | 2,619 → 135 | 2,619 → 135 |

Both capture 16 subsequent outputs. W4 includes five interleaved prefill chunks
(640 tokens), accounting for 20 separate depth traversals, plus seven decode
traversals. Each candidate preparation serves exactly 24 physical layers.

Correlation IDs connect GPU copies to their CPU runtime calls and the innermost
containing annotation. The comparison combines KV write, attention, preparation
and position construction: **97 → 5 transfers/synchronizations per traversal**,
a 94.85% reduction. Metadata transfer bytes fall from 86,528 to 4,096 in W1 and
2,701,248 to 132,608 in W4. Counts include the retained position transfer on
both sides and show removal of repeated per-layer metadata copies.
Gate readbacks remain 64/7 and sampling result
readbacks remain 16/23 in the W1/W4 captures on both sides.

Profiler scopes overlap and include stack collection and observer page scans.
Their durations are diagnostic and cannot be summed into claimed production
savings. The end-to-end timing pairs establish the performance result.
