# 第一批真实 Ouro 性能基线结果（2026-09-15）

> 历史测试：本文对应早期 async 实现，不代表当前代码。后续修复、长上下文、static 和 FA4 测试已完成，统一见 [全部测试汇总](testing_summary_20260915.md)。

## 结论

固定4轮、128输入/512输出的BF16引擎负载下，没有观察到async的稳定加速。
并发1/2/4差异较小；并发8多流D比同步A约慢17%，单流C也明显更慢。
这不是可变深度、SHARED KV、HTTP服务或论文工作负载的结论。

## 配置和测量口径

- 权重：本地Ouro-1.4B，固定release `574fa66cb8bf5abdc979642d01cf2b79b16bfab1`。
- 基础commit：`e525f6460a47adc6805ba0d0c54281786a523deb`；运行时新增测量脚本及未提交文档，源文件快照保存在日志目录。
- 4张B300分别测不同并发：c1/GPU1/CPU16-19，c2/GPU2/CPU24-27，c4/GPU3/CPU32-35，c8/GPU0/CPU8-11。每进程PyTorch CPU线程1，各组不共用GPU。
- BF16、Triton attention、LAST_EXITED、`ouro_delayed`、threshold=1、max_loops=4、greedy、ignore_eos=true。
- 固定num_blocks=1280、block_size=16、max_num_seqs=8、max_num_batched_tokens=128。
- 输入为8条固定英文文本经tokenizer编码、重复并截取为128token；输出均512token。
- A：同步无static/padding；B：同步static+padding；C：B+async单流；D：B+async多流。
- 每组预热一轮满并发完整生成；每次补入请求至少60秒，再排空；加载、预热和文件写入不计时。
- 每并发×每配置3次，按预先确定的随机顺序运行，共48次。计时中收集主机token观测时间，区间前后同步CUDA，不逐步同步。

## 原始结果核对

- 48个trial均产生完整summary和请求记录，无异常日志；每次测量耗时均≥60秒。
- 共完成704个请求、360448个输出token；每请求512token、退出深度全部为4，完成原因为length。
- 逐请求检查时间戳单调、输出计数和最终回收；同一并发下按prompt与A比较，全部原始token IDs一致。
- 这只说明本轮固定4轮工作负载未复现输出差异，**不解决此前可变退出/多请求BF16多流分歧**。
- 正式进程已结束。本轮后台进程没有捕获OS退出码；完整性依据48份结果、原始断言核验和无异常日志，不伪造exitcode=0。

## 限制与后续

1. c1每次仅4个请求、c2每次8个请求；P95/P99样本很少，只描述本批次，不能当稳定尾延迟估计。
2. 采用同一循环输入流，按时间停止补入，C/c8有两次仅24请求，其余c8为32；这些均为完整8prompt周期，但完成工作量不是完全相同。
3. GPU时钟未锁定，只有GPU前后快照和短测资源观察，**未采集完整运行期GPU遥测**；不同并发在不同卡，跨并发缩放混有设备差异。
4. 同机四进程使用不同GPU/CPU亲和性，仍共享主机资源。若需要高置信度绝对数值，应在单卡顺序复测。
5. 此处全部请求固定4轮，未形成论文强调的不同退出深度；多流收益要另测固定可变深度trace。当前结果不能直接断言所有异构负载都无收益。
6. 并发8的退化超出本批重复波动，下一步应单独profile B/C/D的batch组成、CPU等待和CUDA依赖；本批没有足够证据归因于某个具体内核。
7. HTTP TTFT/ITL、真实到达率负载、其他输入长度和SHARED布局均尚未测量。
