858,472 tensor boundaries**, with no missing, invalid or incomparable evidence.

excludes feasibility and the 16 diagnostic BF16-versus-FP32 sensitivity

FP32 satisfies the original `atol=0.001, rtol=0.0001` and exact top-1 gates.

overlap those failures; they are not nine additional independent failures.
Hidden, KV and gate differences remain diagnostics without invented tolerances.

Each dtype has 576 main and 144 live actual prediction pairs. All FP32 tokens
and exits match. BF16 has nine main token mismatches, zero forced-depth
mismatches, and no live token/exit mismatch. Each of those nine main token
mismatches has an exact top-two logit tie on one side and a margin of 0.0625
on the other. Ties remain failures. The closest eligible live-gate CDF distance
from threshold 0.7 is 0.03147808 in FP32 and 0.03066165 in BF16; this finite
fixture set does not cover every decision boundary.

Per dtype, forced executions cover eight distinct fixtures and 14 distinct
adjacent 2-to-4 decode transitions, observed 70 times across implementations,
plus 44 mixed-depth recurrent batches. Supplied input IDs and forced depths
were not counted as independent prediction or gate agreement.

## What is established, and what remains unresolved

The original BF16 depth-four failure [reproduces exactly](initial-20260910.md#gpu-checkpoint-results).

The first required main BF16 failure is Torch serial `Q1-L64-F0`, output zero,
depth-four logits. Recomputing from its saved raw pair gives 55 tolerance
violations. For example, vocabulary entry 3749 is 0.8984375 versus reference
1.2890625: error 0.390625 exceeds the allowed 0.27578125. The selected token
still agrees. This establishes a counterexample independently of summary flags.

A separate, non-tie counterexample is Torch serial `Q1-L128-F0`, output zero:
maximum logit error 3.921875, RMS error 0.89788125, reference RMS 4.42447983.
Both implementations select token 260 with margins 8.125 and 8.6875, but the
required allclose check fails. Matching greedy text cannot qualify this case.

In all 64 main BF16 native trajectories, the first observed nonexact boundary
is depth one, physical layer zero, `attention_output`, which is **after
`o_proj`**. The preceding observed current-row attention input, Q, K and V are
exact. This observation precedes any early-exit propagation, but current-row
equality alone does not prove equality of every historical K/V value or every
paged address read.

For the preselected `Q1-L16-F2` Torch serial case, a raw-byte audit additionally
verifies the entire 16-position first-layer/depth-one K/V prefix and query.
Despite equal stored inputs, 1,175/2,048 post-projection values differ, with
maximum error 0.015625 and RMS error 0.000934084. **This fixture passes all nine
required predictions**, so its internal difference is not itself a failing
counterexample. Native attention keeps FP32 intermediates; official eager
attention rounds QK scores and probabilities to BF16. That code difference is
a hypothesis to isolate, not proof that every later failure has the same cause.

A separately frozen CPU diagnostic used that passing fixture's identical Q/K/V
and one immutable projection weight. It varied only the intermediate rounding
steps, with common FP32 reductions and a common FP64 projection rounded to BF16.
One deterministic pass per variant produced:

| CPU arithmetic variant | RMS versus recorded native | RMS versus recorded oracle |
| --- | ---: | ---: |
| Retain FP32 intermediates | 0.0000323793 | 0.000933526 |
| Insert official BF16 rounding | 0.000934146 | 0.0000107899 |

The variants reproduce 2,042/2,048 and 2,045/2,048 values of their intended
recorded outputs. The predeclared directional-support criterion passes;
exact reproduction fails. The unexplained difference-of-differences has RMS
0.0000341298 against the observed difference RMS 0.000934084. This supports
rounding as a contributor at this passing fixture's first attention block,
with residuals not reproduced by the CPU experiment. It does
not establish the cause of a failed trajectory. The CPU-only replay used
Torch 2.8.0+cpu. Execution took 2.287 seconds and peaked at 288,292,864 RSS bytes;
separate preparation took 3.669 seconds and peaked at 443,666,432 RSS bytes.
Both stayed within the 120-second/1-GiB limits, with 8,564,344 artifact bytes
under the 16-MiB cap. No acceptance tolerance changed.

The required official comparison raises an additional unresolved question.
For `Q1-L128-F0` output zero, official full-sequence BF16 versus the incremental
oracle has maximum error 3.890625 and fails allclose. For `Q1-L256-F0` output
three, allclose passes but official token 281 differs from oracle token 314.
Both corresponding FP32 official checks pass. This competing reference
discrepancy prevents a complete BF16 causal classification.

A focused subsequent investigation should separately freeze oracle prefill of
128 tokens, official prefill of the same 128, and official execution of those
128 plus eight causally masked future tokens. Capture the pre-projection
attention context as well as existing boundaries. This distinguishes the
oracle/official execution path from total-sequence-shape effects, including
projection GEMM dimensions. That proposal has not been executed and is not a
replacement trial in this suite.
